"Vulnerabilidad de código"
Es un fallo, error o debilidad de programación en el código fuente; esto se debe a falta de validación, error humano o malas prácticas.

Solución en proyectos: recibes un reporte en donde identificas el problema, revisas tu código y haces las pruebas necesarias. Una vez que identificaste el error, modificas tu código si es necesario y ejecutas la aplicación para verificar que el error se corrigió y no te generó ningún cambio no deseado. Después, subes tus cambios a una rama para que el equipo los revise y valide con los análisis de seguridad, para comprobar que ya no hay ninguna vulnerabilidad.
(Herramientas: GitHub Code Security, OWASP)

"Vulnerabilidad de seguridad"
Es una debilidad en el sistema, aplicación o servidor que podría ser aprovechada para acceder a la información que hay dentro.
Para poder corregirla debemos:
1. Identificar el problema.
2. Corregirlo, es decir, modificar el código, actualizar la librería, corregir permisos o cambiar la configuración.
3. Realizar pruebas para comprobar si se solucionó el problema.
4. Subir tus cambios y solicitar una revisión con tu equipo.

"Obsolescencia"
Estado en el que un servicio deja de ser útil, funcional o adecuado. En el caso de programación, cuando una función, característica, biblioteca o lenguaje de programación se considera anticuado; esto a su vez deja de recibir soporte.
Para poder corregirlo:
1. Identifica qué es lo que está obsoleto.
2. Busca la alternativa actual.
3. Actualiza las dependencias; en este caso, si la librería es obsoleta, revisa si tiene una versión moderna y si es compatible y si se le da mantenimiento.
4. Prueba tus cambios.

Recuerda que para corregir cualquiera de las 3 anteriores es importante que identifiques el problema con un reporte que te deben pasar. Una vez que tengas esto, si ocupas la IA, debes ser muy preciso en lo que le pedirás ayuda para que te apoye a corregir lo adecuado y siempre tiene que probar que no tenga cambios que antes no reconocías.

Ejemplo de vulnerabilidad:

Necesitamos el reporte para ver los errores que tenemos. Para ello, entramos a Kiwan, luego nos vamos a Search y buscamos el nombre de nuestro proyecto (multiplan). Una vez estando ahí, damos clic en "like" para ver el estatus y luego clic en las 3 rayitas en la mano izquierda. Nos aparece "Defect". Si vemos algún defecto, entonces lo debemos arreglar. Nos dirigimos a nuestro entorno de trabajo y le pedimos a la IA que nos ayude a corregir la vulnerabilidad o defecto. Una vez que lo hacemos, ponemos en el chat qué cambios queremos que aplique. Después de ello, lo ejecutamos con "mvn clean install". Una vez que lo ejecuta, nos dirigimos al servidor, entramos con la contraseña correspondiente. Una vez dentro, ponemos "cd" y la ruta que queremos. Luego vamos a PuTTY, copiamos el archivo del lado izquierdo al derecho y revisamos que el archivo sea el correcto. Después de verificar esto, nos regresamos al ID, escribimos "git branch" para ver la rama en la que estamos. Luego de verificar que estamos en la rama correcta, ponemos "git status" para ver que el cambio se hizo. Ojo: el archivo en como termine es lo que hay que copiar. Ponemos un "git add" y el archivo con la ruta completa. Al estar en rojo, significa que está editado pero que aún no se han subido los cambios. Una vez que veamos esto, ponemos un "git add" y la ruta. Después, colocamos "git status" para ver el cambio en verde; luego, un "git commit -m "Cambio"" y por último un "git push".

Ahora lo verificamos en el repositorio. Entramos a GitHub, a la rama correcta y buscamos paso a paso, mediante el nombre del archivo, el cambio que hicimos y actualizamos para ver nuestro cambio.

"Sistema Cloud": una red global de servidores remotos conectados a internet que almacenan y procesan datos en lugar de hacerlo en el disco duro de tu computadora o celular.
Almacena archivos, accedes desde cualquier lugar, trabajas en tiempo real, usas aplicaciones sin instalar y respaldas información.
Se alojan y administran en una instalación remota propiedad de un proveedor (AWS o Microsoft Azure).

"On-premise":
Un modelo de instalación donde el software y la infraestructura de tecnología se alojan y ejecutan localmente en servidores propios con control total, gestión interna e independencia, y las ventajas son privacidad y seguridad.
Los servidores de almacenamiento y software se mantienen dentro de una instalación física en una empresa.

La diferencia entre ambos es el lugar donde se almacenan los datos y se ejecuta el software.
En on-premise, se utilizan servidores físicos locales dentro de la propia empresa, mientras que cloud utiliza servidores remotos gestionados por un proveedor externo a través de internet.

"Comandos Maven en Java"
- mvn clean: borra los archivos generados anteriormente, principalmente la carpeta target.
- mvn compile: compila el código fuente del proyecto.
- mvn package: compila, prueba y genera el archivo JAR o WAR.
- mvn install: genera el paquete y lo instala en tu repositorio local de Maven.
- mvn clean install: limpia el proyecto, luego compila, prueba y empaqueta.
- mvn clean package: limpia y genera nuevamente el JAR o WAR.
- mvn dependency:tree: muestra las librerías/dependencias que utiliza el proyecto.
- mvn validate: verifica que la estructura y la configuración del proyecto sean correctas.
- mvn verify: ejecuta las verificaciones necesarias después de las pruebas y antes de instalar o publicar.
